{{- if and .Values.worker.enabled (not .Values.s3.enabled) (ne (.Values.config.INQTRIX_OBJECT_STORE_BACKEND | toString) "s3") }}

WARNING: the worker does NOT share the object store with the api here. With the
local backend each pod gets its own emptyDir, so artifacts written by one are
invisible to the other (a silent partition); a ReadWriteOnce PVC
(persistence.enabled) only works if both pods land on the same node, else one
stays Pending (Multi-Attach). Give the worker shared storage: --set s3.enabled=true
(bundled MinIO) or --set config.INQTRIX_OBJECT_STORE_BACKEND=s3 plus the S3 credentials.
{{- end }}
{{- if and .Values.openshift.enabled .Values.postgres.enabled }}

WARNING: openshift.enabled with a bundled postgres. The official postgres image needs
a fixed UID (its initdb looks up the UID in /etc/passwd) and will NOT start under the
default restricted-v2 SCC (the pod is rejected and the auto-wired INQTRIX_DATABASE_URL
points at a Service with no endpoints). Use an external/managed database on OpenShift
(set INQTRIX_DATABASE_URL), or a permissive SCC. Bundled qdrant/valkey/s3 are fine on
OpenShift (they run under the arbitrary UID).
{{- end }}

Verify the deployment:
  kubectl -n {{ .Release.Namespace }} wait --for=condition=ready pod -l app.kubernetes.io/instance={{ .Release.Name }} --timeout=5m
  helm test {{ .Release.Name }} -n {{ .Release.Namespace }}

Scaling note: more than one API replica requires the postgres storage backend,
a Valkey queue with worker.enabled, and the S3 object-store backend (a local
PVC is ReadWriteOnce and not shared across pods). See docs/deployment/kubernetes.md.
